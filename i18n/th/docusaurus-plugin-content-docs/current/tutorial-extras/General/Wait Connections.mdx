# Wait Connections Workflow

Example workflow demonstrating the **Wait Connections** block, an advanced flow control instruction used to synchronize multiple parallel execution branches before proceeding. Ideal for parallel processing workflows where upstream branches must complete before the next step executes.

## Interactive Workflow Preview

Click on blocks to view and edit settings. Drag background to pan, use scroll wheel to zoom in/out.

## Workflow Blocks

| Block | Type | Description |
|-------|------|-------------|
| **Start (Trigger)** | `BlockBasic` | Workflow entry point. |
| **Open URL** | `BlockBasicWithFallback` | Opens target webpage. |
| **Blocks Group** | `BlockGroup` | Group block encapsulating parallel execution branches (contains Browser Request blocks). |

## Wait Connections Block Settings

### Main Parameters

| Parameter | Description | Default |
| :--- | :--- | :--- |
| **Description** | Custom note or description for this block | Empty |
| **Timeout (milliseconds)** | Maximum duration to wait for all branch connections to complete (supports `{x}` variables) | `10000` (10 seconds) |
| **Only continue a specific flow** | When enabled, proceeds only on specified flow branch instead of waiting for all branches | Off |

### Settings Parameters

| Parameter | Description |
| :--- | :--- |
| **Timeout (millisecond)** | Maximum runtime timeout in milliseconds |
| **Delay time (millisecond)** | Pre-execution delay duration before evaluating connections |

---

### Use Cases

* **Parallel Branch Synchronization**: Wait for parallel operations (e.g. scraper tasks & stats fetching) to finish before proceeding.
* **Rate Limiting / Throttling**: Use with Timeout to throttle concurrent network operations.
* **Conditional Branch Continuation**: Enable `Only continue a specific flow` to advance as soon as a designated fast branch finishes.
