# Blocks Group Workflow

Example workflow demonstrating the **Blocks Group** block, a container block used to group, organize, or isolate sub-blocks to maintain a clean canvas layout and modularize workflow sub-routines.

## Interactive Workflow Preview

Click on blocks to edit settings. Hover blocks and click **"Move to Group"** on the floating toolbar to move blocks into the group! Click **`×`** on group items to move them back out.

<WorkflowPreview data={blocksGroupData} height={580} />

## Workflow Blocks

| Block | Type | Description |
|-------|------|-------------|
| **Start (Trigger)** | `BlockBasic` | Workflow entry point. |
| **Open URL** | `BlockBasicWithFallback` | Opens target webpage. |
| **Blocks Group** | `BlockGroup` | Container block encapsulating nested sub-blocks. |
| **Browser Request** | `BlockBasicWithFallback` | HTTP Request block (rendered outside in preview for move-to-group testing). |

## Blocks Group Features & Settings

The **Blocks Group** block functions like a folder for workflow nodes, reducing canvas clutter in complex automations.

### Parameters

| Parameter | Description | Options & Details |
| :--- | :--- | :--- |
| **Group name** | Descriptive group title | Enter name e.g., `Fetch Profile Data`, `Account Login Flow` |
| **Nested Blocks** | Sub-blocks inside the group | Rendered as stacked items executed sequentially within the group |

---

### Interactive Group Controls

* **Moving Blocks Into Group**:
    1. Click or hover over any node on the canvas (e.g. **Browser Request**).
    2. Click the **"Move to Group"** icon on the floating toolbar.
    3. The block is automatically encapsulated into the **Blocks Group** container.
* **Moving Blocks Out of Group**:
    1. Click the **`×`** icon on any nested item inside the **Blocks Group**.
    2. The sub-block is extracted back to the main canvas canvas plane.
