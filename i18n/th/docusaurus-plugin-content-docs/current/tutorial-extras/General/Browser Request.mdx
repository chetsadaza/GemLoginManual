# Browser Request Workflow

Example workflow demonstrating the **Browser Request** block, used to execute HTTP requests (GET, POST, PUT, PATCH, DELETE, HEAD) directly inside the active browser context. Automatically utilizes current cookies, headers, and authentication sessions to interact with target APIs.

## Interactive Workflow Preview

Click on blocks to view and edit settings. Drag background to pan, use scroll wheel to zoom in/out.

## Workflow Blocks

| Block | Type | Description |
|-------|------|-------------|
| **Start (Trigger)** | `BlockBasic` | Workflow entry point. |
| **Open URL** | `BlockBasicWithFallback` | Opens target webpage to establish cookies and session context. |
| **Browser Request** | `BlockBasicWithFallback` | Executes in-browser HTTP API request using active browser session. |

## Browser Request Block Settings

The **Browser Request** block supports custom Headers, Body payloads, and Response Extraction.

### Main Parameters

| Parameter | Description | Options & Details |
| :--- | :--- | :--- |
| **Request method** | HTTP Method | `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD` |
| **Request URL\*** | Target API URL | Supports variable interpolation `{x}` (e.g. `{{variables.api_endpoint}}`) |
| **Content type** | Body payload content type | `application/json` (default), `text/plain`, `multipart/form-data`, `application/x-www-form-urlencoded` |
| **Timeout (0 to disable)**| Maximum response wait time (ms) | Enter `10000` (10s) or `0` to disable |

### Configuration Tabs

* **Headers**: JSON Object containing request headers (e.g. `{"Authorization": "Bearer token"}`).
* **Body**: Payload content attached to the request (e.g. `{"name": "GemLogin"}`).
* **Response**:
    * **Data path type**: Response data format (`JSON`, `Text`, `Headers`).
    * **Data path**: Property path to extract (e.g. `data.user.id`).
    * **Assign to variable**: Save extracted response into workflow variable.
    * **Insert to table**: Insert extracted response into database table columns.

---

### Key Advantages & Use Cases

* **Bypass Authentication Prompts**: Executes within active browser contexts, carrying valid session cookies automatically to fetch protected API data without re-authenticating.
* **Real-time API Ingestion**: Direct JSON extraction from internal REST APIs into database tables.
