# คำถามที่พบบ่อย (FAQs)

รวบรวมคำถามและคำตอบที่พบบ่อยเกี่ยวกับ **Covertia Anti-detect Browser & Automation Platform**

---

## Browser Profile

<Details summary="Browser Profile คืออะไร?">

Browser Profile คือสภาพแวดล้อมเบราว์เซอร์ที่แยกเป็นเอกเทศ (Sandbox) โดยแต่ละโปรไฟล์จะมีลายนิ้วมือเบราว์เซอร์ (Fingerprint), คุกกี้ (Cookies), หน่วยเก็บข้อมูลในเครื่อง (Local Storage) และการตั้งค่าเครือข่ายของตัวเอง ซึ่งจะทำให้แต่ละโปรไฟล์ดูเหมือนมาจากคนละอุปกรณ์ ป้องกันการเชื่อมโยงข้ามบัญชี

</Details>

<Details summary="วิธีการสร้างโปรไฟล์ทำอย่างไร?">

วิธีการสร้างโปรไฟล์มี 4 รูปแบบหลัก:

| รูปแบบการสร้าง | เหมาะสำหรับ |
|------|----------|
| **Single Create** | สร้างทีละโปรไฟล์ พร้อมระบุการตั้งค่าอย่างละเอียด |
| **Multiple Create** | สร้างโปรไฟล์หลายตัวพร้อมกันอย่างรวดเร็ว |
| **Import File** | นำเข้าโปรไฟล์จำนวนมากผ่านไฟล์ Excel (.xlsx / .csv) |
| **Import from External** | ตรวจสอบและนำเข้าโปรไฟล์ที่มีอยู่แล้วจาก Chrome |

</Details>

<Details summary="ทำไมลายนิ้วมือเบราว์เซอร์ (Fingerprint) ต้องสอดคล้องกัน?">

ข้อมูลลายนิ้วมือเบราว์เซอร์ต้องมีความสอดคล้องกับเครือข่ายเพื่อความปลอดภัยสูงสุด:

```
✅ IP ตรงกับประเทศ
✅ ประเทศตรงกับเขตเวลา (Timezone)
✅ ภาษาตรงกับภูมิภาคของ IP
✅ เวอร์ชันเบราว์เซอร์สมจริง
✅ พิกัดทางภูมิศาสตร์ (Geolocation) ตรงกับ IP
```

ตัวอย่าง **ความเสี่ยงสูงที่จะถูกตรวจจับ**:

```
❌ IP เวียดนาม + เขตเวลาสหรัฐฯ + ภาษาลัตเวีย + ระบบปฏิบัติการ Windows แต่ใช้ MacOS User-Agent
```

</Details>

<Details summary="การตั้งค่าพร็อกซี (Proxy) ทำอย่างไร?">

SOCKS5 (แนะนำ):

```
host:port:username:password
```

HTTP:

```
http://ip:port:username:password
```

โปรดคลิกปุ่ม **Check** เพื่อทดสอบพร็อกซีก่อนเริ่มใช้งานเสมอ เพื่อตรวจสอบสถานะ IP และคุณภาพการเชื่อมต่ออินเทอร์เน็ต

</Details>

<Details summary="แนะนำให้ใช้งานเบราว์เซอร์ตัวใด?">

**Chrome** — แนะนำสำหรับใช้งานทั่วไป เนื่องจากรองรับเว็บไซต์ส่วนใหญ่ได้ดี ลายนิ้วมือเบราว์เซอร์เป็นธรรมชาติ มีเสถียรภาพ และรองรับส่วนเสริม (Extensions) ได้ครบถ้วน

</Details>

<Details summary="ควรเลือกใช้งานเบราว์เซอร์เวอร์ชันใด?">

```
✅ เวอร์ชันเสถียรล่าสุด เช่น 138, 139, 140, 141
❌ เวอร์ชันที่เก่ามากเกินไป
❌ เวอร์ชันทดลอง (Beta / Canary)
```

</Details>

## Fingerprint & Security

<Details summary="Covertia สามารถจำลอง (Spoof) อะไรได้บ้าง?">

| หมวดหมู่ | ตัวเลือกการตั้งค่า |
|------|----------|
| **Canvas** | `real` (จริง) / `noise` (เพิ่มสัญญาณรบกวน) |
| **WebGL Image** | `real` / `noise` |
| **WebGL Metadata** | `real` / `custom` (จำลองรุ่นการ์ดจอ) |
| **Audio Context** | `real` / `noise` |
| **WebRTC** | `replace` (แทนที่) / `real` / `disabled` (ปิด) |
| **Fonts** | `default` (เริ่มต้น) / `custom` (กำหนดเอง) |
| **Hardware Concurrency** | 2, 4, 8, 10, 12, 16, 20, 24 คอร์ |
| **Device Memory** | 2, 4, 8, 10, 12, 16, 20, 24 GB |
| **Screen Resolution** | `random` (สุ่ม) / `custom` |
| **MAC Address** | `real` / `custom` |
| **Do Not Track** | `default` / `open` / `close` |
| **Port Scan Protection** | `accept` / `decline` |

</Details>

<Details summary="ควรเลือกใช้ noise หรือ real?">

- **noise**: ช่วยเพิ่มสัญญาณรบกวนเพื่ออำพรางลายนิ้วมือจริง — **แนะนำ** สำหรับงานที่ต้องการความปลอดภัยสูงและทำงานพร้อมกันหลายบัญชี
- **real**: ใช้ลายนิ้วมือจริงของเครื่องคอมพิวเตอร์ของคุณ — เหมาะสำหรับการใช้งานบัญชีเดียวทั่วไป แต่มีความเสี่ยงหากรันหลายโปรไฟล์พร้อมกัน

</Details>

## Workflows

<Details summary="Workflow คืออะไร?">

Workflow คือสคริปต์อัตโนมัติที่ทำงานภายในเบราว์เซอร์เป้าหมาย — ใช้ในการทำงานซ้ำ ๆ เช่น ล็อกอินอัตโนมัติ, การฟาร์มบัญชี, การกรอกฟอร์ม และสามารถเลือกสั่งงานข้ามโปรไฟล์หลายตัวได้

</Details>

<Details summary="วิธีการสร้าง Workflow ทำอย่างไร?">

1. ไปที่เมนู **Workflows**
2. คลิกปุ่ม **New workflow**
3. กรอก **Name** (แนะนำระบุเวอร์ชันและแพลตฟอร์ม เช่น `v1.0.0 Facebook Auto Login`)
4. กรอก **Description** (สูงสุด 300 ตัวอักษร)
5. คลิก **Create** เพื่อเริ่มเขียนแผนภาพ

</Details>

<Details summary="สามารถนำเข้า (Import) Workflow ได้ไหม?">

**ได้** — คลิกที่ปุ่ม **Import** และอัปโหลดไฟล์เวิร์กโฟลว์ที่คุณบันทึกไว้เข้าสู่ระบบได้ทันที

</Details>

<Details summary="จัดการเวิร์กโฟลว์จำนวนมากอย่างไร?">

- **Search**: ค้นหาเวิร์กโฟลว์ตามชื่อ
- **Delete**: ลบรายตัวหรือกดเลือก Checkbox ด้านหน้าเพื่อลบแบบกลุ่ม (Bulk Delete)
- **Version**: ตรวจดูเลขเวอร์ชันของสคริปต์ได้ในคอลัมน์ชื่อ

</Details>

## Tasks (Scheduling)

<Details summary="Task กับ Workflow แตกต่างกันอย่างไร?">

| คุณสมบัติ | Workflow | Task |
|------|----------|------|
| คำนิยาม | ตัวสคริปต์ขั้นตอนการทำงาน | การนำสคริปต์ไปตั้งเวลารันงานจริง |
| วิธีรัน | ต้องกดสั่งรันด้วยตนเอง | ทำงานอัตโนมัติเมื่อถึงเวลา |
| โปรไฟล์เป้าหมาย | ❌ ไม่สามารถระบุไว้ล่วงหน้าได้ | ✅ เลือกเป็นรายโปรไฟล์หรือกลุ่มได้ |
| เธรดทำงานพร้อมกัน | ❌ ทำงานทีละโปรไฟล์ | ✅ กำหนดจำนวน Concurrent Threads ได้ |
| รูปแบบหน้าต่าง | ❌ | ✅ กำหนดพิกัดขนาดและการจัดวางได้ |

</Details>

<Details summary="มีตัวเลือกการตั้งเวลาแบบใดบ้าง?">

| ความถี่การทำงาน | ลักษณะการรัน |
|-----------|----------|
| **Immediate** | เริ่มรันงานทันทีหลังกดสร้าง Task |
| **Once** | รันเพียงครั้งเดียวตามวันและเวลาที่กำหนด |
| **Interval** | รันซ้ำอย่างต่อเนื่องตามคาบเวลาที่ระบุ (เช่น ทุก 30 นาที) |
| **Every day** | รันอัตโนมัติทุกวันในเวลาเดิม |

</Details>

<Details summary="ควรตั้งค่า Concurrent Threads (เธรดทำงานพร้อมกัน) จำนวนเท่าใด?">

- ค่าเริ่มต้นคือ **10** เธรด (รันได้ 10 โปรไฟล์พร้อมกัน)
- ปรับเพิ่มขึ้นได้หากสเป็ก CPU/RAM ของเครื่องแรงพอ เพื่อรันงานได้รวดเร็วยิ่งขึ้น
- ปรับลดลงหากเครื่องคอมพิวเตอร์ช้าลง หรือพร็อกซีของคุณจำกัดความเร็วและจำนวนการเข้าถึง

</Details>

<Details summary="Open time between profiles (เวลาหน่วงในการเปิดโปรไฟล์) คืออะไร?">

ระยะเวลาหน่วงหน่วยเป็นมิลลิวินาที (ms) ก่อนเริ่มเปิดโปรไฟล์เบราว์เซอร์ตัวถัดไป — ค่าเริ่มต้นคือ 300ms ช่วยลดภาระการทำงานของทรัพยากรระบบคอมพิวเตอร์ และป้องกันไม่ให้ไอพีของพร็อกซีรับส่งข้อมูลเร็วเกินไปจนโดนจำกัดสิทธิ์ (Rate Limit)

</Details>

## Database

<Details summary="Tables, Variables และ Credentials แตกต่างกันอย่างไร?">

| ฟีเจอร์ | วัตถุประสงค์การใช้งาน | ตัวอย่าง |
|---------|----------|---------|
| **Tables** | เก็บข้อมูลเชิงโครงสร้างเป็นตาราง (แถว/คอลัมน์) | รายชื่อบัญชี, ข้อมูลที่ดึงได้จากเว็บ |
| **Variables** | เก็บค่าตัวแปรในรูปแบบคู่คีย์-ค่า (Key-Value) | พารามิเตอร์รันไทม์, แฟล็กสถานะสคริปต์ |
| **Credentials** | เก็บข้อมูลสำคัญและเป็นความลับ (เข้ารหัสปลอดภัย) | รหัสผ่านบัญชี, API Tokens |

</Details>

<Details summary="ตารางข้อมูล (Tables) รองรับประเภทข้อมูล (Data Types) แบบใดบ้าง?">

- `Any` — ข้อมูลรูปแบบใดก็ได้
- `Text` — ข้อความและตัวอักษr
- `Number` — ข้อมูลประเภทตัวเลข
- `Boolean` — ค่าความจริง True/False
- `Array` — ข้อมูลแบบรายการโครงสร้างต่อเนื่อง

> ⚠️ การลบข้อมูล Tables, Variables หรือ Credentials จะเป็นการลบถาวร โปรดตรวจสอบเวิร์กโฟลว์ที่ใช้งานข้อมูลเหล่านี้ก่อนกดยืนยัน

</Details>

## Developer API

<Details summary="มีระบบ API สำหรับนักพัฒนาไหม?">

**มี** — ระบบหลักของ Covertia ทำงานผ่าน API พอร์ตโลคอลที่ `http://localhost:1010`:

| Endpoint | หน้าที่การทำงาน |
|----------|----------|
| `/api/profiles` | จัดการโปรไฟล์ (สร้าง, ลบ, เปิด, ปิด, เช็คสถานะ) |
| `/api/scripts` | เรียกดู รายการสคริปต์, สั่งรันงาน, หรือสั่งหยุดสคริปต์ |
| `/api/groups` | แสดงรายการกลุ่มของโปรไฟล์เบราว์เซอร์ |
| `/api/browser_versions` | เรียกดูเวอร์ชันเบราว์เซอร์ที่พร้อมใช้งาน |
| `/api/locations` | ค้นหาพื้นที่ภูมิศาสตร์และประเทศที่ระบบรองรับ |

</Details>

## Troubleshooting

<Details summary="โปรไฟล์ดูน่าสงสัย / บัญชีถูกแบนบ่อยครั้ง?">

โปรดใช้ **รายการตรวจสอบความสอดคล้องลายนิ้วมือ (Fingerprint Consistency Checklist)** ดังนี้:

1. IP ตรงกับประเทศจริงหรือไม่?
2. เขตเวลา (Timezone) ตรงกับพิกัด IP หรือไม่?
3. ภาษาของเบราว์เซอร์สอดคล้องกับประเทศของ IP หรือไม่?
4. User-Agent ระบุรุ่นระบบปฏิบัติการสอดคล้องกับสเป็กจริงหรือไม่?
5. Geolocation ตรงกับพิกัดตำแหน่งของพร็อกซีหรือไม่?
6. เวอร์ชันเบราว์เซอร์เป็นรุ่นล่าสุดสมจริงหรือไม่?

</Details>

<Details summary="พร็อกซีไม่ทำงาน?">

1. คลิกปุ่ม **Check** เพื่อทดสอบเชื่อมต่อในหน้าต่าง Profile → Network
2. ตรวจสอบรูปแบบการพิมพ์: `host:port:username:password`
3. ตรวจสอบให้มั่นใจว่าประเภทของพร็อกซี (Proxy Type) ตรงกับผู้ให้บริการจริง (SOCKS5 / HTTP)

</Details>

<Details summary="งาน (Task) ไม่ทำงานตามเวลาที่ตั้งไว้?">

- **Starting Time** ต้องถูกตั้งเวลาล่วงหน้าห่างจากปัจจุบันอย่างน้อย **2 นาที**
- ต้องเปิดสวิตช์สถานะ **ON/OFF** (แถบสีเขียว) บนหน้าจัดการงาน
- ต้องเลือกโปรไฟล์เบราว์เซอร์เป้าหมายอย่างน้อย 1 ตัวในแท็บ **Profiles**
- เข้าตรวจสอบบันทึกย้อนหลังได้ในหน้า **Schedule History**

</Details>

<Details summary="การนำเข้าไฟล์ (Import File) ไม่ผ่านการตรวจสอบความถูกต้อง?">

- ดาวน์โหลด **Template File** ของระบบมาใช้งานก่อนกรอกข้อมูลจริง
- ช่องคอลัมน์ **Name** ห้ามเว้นว่างเด็ดขาด
- ตรวจสอบพร็อกซีให้อยู่ในฟอร์แมต `ip:port:username:password` เท่านั้น
- สามารถตรวจเช็คจำนวนโปรไฟล์ที่ถูกต้อง/ไม่ผ่านเกณฑ์ได้ในหน้า **Profile Stats** ก่อนกดยืนยัน

</Details>
